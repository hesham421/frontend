## 4️⃣ Key Gaps / Risks

**Confirmed, reproducible defects** (failed consistently across ≥2 independent test cases in this run):
1. **Permission Matrix checkboxes don't persist** (TC017, TC024) — corroborates the 2026-08-28 run's "remove page doesn't persist" finding. This is the highest-priority fix: it blocks all RBAC permission editing from the UI.
2. **Page Registry has no visible Create control** (TC016, TC023) — either a missing feature or a permission-gated button the seeded admin can't see; needs source inspection of `src/pages/Security/Pages.tsx`.

**Likely environment limitations, not product bugs** (needs a real token to confirm either way):
3. Account activation and password reset both require an out-of-band token (email) this headless run cannot read (TC002, TC006, TC007, TC008, TC009). To get real signal here in future runs, either wire up a test mailbox/SMTP catcher the agent can read, or expose a test-only "last issued token" endpoint gated to non-prod environments.

**Contradictory results within the same run — needs manual re-check before triaging as bugs:**
4. Role edit Save button: TC019 succeeded, TC020 reported no Save control visible on the same screen. Possibly dirty-state gating (button only appears after a field changes) — reproduce manually.
5. Page entry edit Save button: TC026 succeeded, TC023 reported no Save control visible. Same hypothesis as #4.
6. Role creation: TC013 reported no Create control found, TC015 succeeded on the same screen in the same run — likely a scroll/render-timing false negative in TC013, not a real gap.
7. Assigned Roles picker: TC014 and TC030 both passed, which is a **positive signal** against the 2026-08-28 run's "picker unresponsive" bug — worth a quick manual spot-check to confirm it's actually fixed rather than intermittent.

**New finding needing a follow-up isolated test:**
8. Deleting a user with pre-existing linked data (roles, profile, etc.) fails with a conflict error (TC027) — needs a follow-up run against a freshly-created user with zero linked records to determine whether this is a genuine delete-flow bug or expected referential-integrity behavior that just needs a clearer error message.

**Out of scope for this run:** Organization module and Notifications module (Notifications is mock/local-state only, not backend-connected) were intentionally excluded — this run targeted SECURITY only per the request.
