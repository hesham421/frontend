4️⃣ Key Gaps / Risks

  1. Permission Matrix checkboxes don't persist (TC017, TC024) — corroborates the 2026-08-28 run's "remove page doesn't persist" finding. Highest-priority fix: blocks all RBAC permission editing from the UI.
  2. Page Registry has no visible Create control (TC016, TC023) — either a missing feature or a permission-gated button the seeded admin can't see; needs source inspection of src/pages/Security/Pages.tsx.
  3. Activation/reset flows can't be verified from a headless run (TC002, TC006, TC007, TC008, TC009) — tokens are delivered by email this run can't read. Wire up a test mailbox/SMTP catcher or a test-only "last issued token" endpoint (non-prod only) to get real signal here.
  4. Role edit Save button: TC019 succeeded, TC020 found no Save control on the same screen — possibly dirty-state gating. Reproduce manually.
  5. Page entry edit Save button: TC026 succeeded, TC023 found no Save control — same hypothesis as #4.
  6. Role creation: TC013 reported no Create control, TC015 succeeded on the same screen in the same run — likely a scroll/render-timing false negative in TC013, not a real gap.
  7. Assigned Roles picker: TC014 and TC030 both passed — a positive signal against the 2026-08-28 run's "picker unresponsive" bug. Worth a quick manual spot-check to confirm it's actually fixed rather than intermittent.
  8. Deleting a user with linked data fails with a conflict (TC027) — needs a follow-up run against a freshly-created user with zero linked records to determine whether this is a genuine bug or expected referential-integrity behavior needing a clearer message.
